## 初版在线链路

- `services/structured_nutrition.py` 负责明确日期、相对日期、餐次和食物份量。支持今天、昨天、前天、近N天、近一周、本周、上周和 ISO 起止日期，单次范围1至31天。它采用规则解析，尚非任意自然语言日期解析器。
- 确定的日期与餐次交给参数化数据库查询，热量和营养按克重在程序中换算与汇总。单日全餐记录可计算与目标热量的剩余或超额。
- 食物匹配遍历当前食物目录，匹配完整名称和去掉状态括号的名称，优先保留更长的非重叠名称。少量现有别名显式维护，未使用模型生成SQL。
- 记录为空时状态为 no_records，合计为null；营养字段缺失为null。旧的其他业务营养计算接口仍保留原有兼容行为，本次完善的未知值处理针对 RAG 上下文。
- 聊天按分句判断是否可只查结构化数据。每个分句都明确属于结构化查询时跳过菜谱，有烹饪线索或意图不清时保留检索。
- 食物营养使用 [D1] 等数据库来源编号，菜谱使用 [R1] 等编号。消费记录与程序合计直接说明日期和实际份量。

## 22 道真实联动题

题目位于 `database_rag_cases.json`，包括今天/昨天/指定日期、午餐、近三天汇总、单食物与多食物克重、FDA来源及生熟状态、热量目标、体重趋势、过敏原、空记录、未知营养、超范围日期、混合菜谱问题、要求篡改数字和历史指代。

```powershell
python backend/evals/evaluate_database_rag.py
```

该命令调用真实 MySQL、当前配置的菜谱向量库和云端模型，可能加载已有 BGE-M3。请在授权运行模型的前提下执行。仅使用模拟账户，不读取真实用户进行测评。直接调用聊天共用的 `pipeline.answer`，不伪造数据库或模型结果，不写聊天记录。

期望营养数字由独立的SQL查询和份量计算得到，未提供给模型。程序检查取数日期、餐次、合计、回复中的数字和必要词。数值出现和关键词匹配只做自动初筛，可能漏判单位、归属、额外错误陈述等问题，需要阅读完整回答。完整问答与真实上下文保存在 Git 忽略的 `evals/outputs/` 下。

第一轮 `database_rag_20261118_v1` 的 db02 发现“昨天，不要混入今天”取数范围过大，模型虽给出正确昨日数值，结构化检查仍判失败。人工审阅还发现 db07 将数据库营养错误引用到菜谱编号。后续修正了日期排除表达、来源编号，并减少纯数据库问题的无关菜谱引用。最终复测见 `database_rag_20261118_v2`。

2026-11-18 复测22题自动初筛全部通过，已阅读回答检查主要数字、日期、缺失信息和来源编号。模拟数据的今日登记274.8 kcal、昨日130 kcal、今日午餐74.8 kcal和蛋白4.6 g均正确。另通过真实 `/api/chat/sync` 入口验证了回答与消息持久化，结果存于该输出目录的 `api_smoke.json`。41项相关自动化测试通过。这些结果只覆盖本轮模拟场景，自动初筛通过率不等于通用回答准确率。

## 双来源专项

`database_recipe_cases_v2.json` 包含 9 道同时依赖数据库和菜谱证据的日常问题。题目描述用户想知道什么，系统自行选择数据来源。专项使用模拟账户最近一次登记日期及前两天，明写日期方便之后复跑。脚本直接调用聊天共用的 Python 流程，运行只需要 MySQL、现有向量索引和模型配置。

```powershell
python backend/evals/evaluate_database_rag.py --suite joint
```

数据库端核对日期、餐次、营养值和单位，菜谱端按来源、章节、文字定位证据块，检查正文引用编号是否覆盖每组证据，并筛查答案中的菜谱数值和单位。这是自动初筛，数值与引用在正文同时出现仍需要阅读答案来确认是否关联正确。

原版用 `--suite joint-v1` 复跑。新版沿用题号、模拟数据和证据标准，只改提问措辞。首轮原版 9 道题均答对数据库部分，2 道完整通过。6 道被规则归为纯结构化问题，跳过了菜谱检索。另有 1 道鸡蛋羹对比题只检索到微波炉版本，缺少蒸箱版本。原版输出见 `outputs/database_recipe_joint_v1/summary.md`。

自然问法版实测 4/9 完整通过。2 题跳过了菜谱检索，2 题把“午饭”解释成了全天范围（其中 1 题同时跳过菜谱），另有 2 题的份量换算从恰好同重量的历史饮食记录得到了正确数字，但未触发食物营养查询。报告仍把这些判为需要复核，避免把碰巧正确的数字算成正确的取数路径。输出见 `outputs/database_recipe_joint_v2/summary.md`。

接入结构化查询计划后，同样的 9 道自然问法题全部通过自动初筛，见 `outputs/database_recipe_joint_planner/summary.md`。
