未更改检索算法、向量库、模型或问题改写逻辑。

## 新规则

每份 evidence 仍表示一个需要回答的事实。其 alternatives（等价证据）与原证据是 OR（任选一份可支持同一事实）。
不同 evidence 条目之间依然分别计入证据组覆盖率，例如双问题必须找齐两个事实。
等价证据固定在同一道菜的原文内，每个 locator（证据定位条件）均校验章节及原文真实存在。

## 解读限制

v1/v2 的标准答案集合不同，不能把两份报告的分数变化称为算法提升。
补充多个等价块后，块级 Recall（召回率）分母会变大；应结合 evidence_hit（是否命中事实）和 evidence_group_coverage（所需事实覆盖率）解读，不能为了追回所有重复表达而增加无用上下文。
未来各新模块统一使用 v2，同题库摘要和语料摘要匹配后再比较。
仅5道开发集无答案题，阈值结果只是开发样本取舍，不能宣称适用于所有用户问题。

## 运行与回放

```powershell
python backend/evals/evaluate_retrieval.py --validate-only
python backend/evals/evaluate_retrieval.py --split dev --ks 1 3 5 --output backend/evals/outputs/dense_dev_raw_v2
python backend/evals/sweep_thresholds.py backend/evals/outputs/dense_dev_raw_v2/report.json --output backend/evals/outputs/dense_dev_raw_v2_thresholds
```

第一条不加载模型；第二条会实际加载本地 BGE-M3；第三条直接回放第二条保存的候选，不重复推理。
阈值回放只适用于余弦距离，且 K 不超过已保存候选池大小；不适用于 BM25 或重排分数。
这些阈值不会自动写入聊天配置。
