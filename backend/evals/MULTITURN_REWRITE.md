# 多轮查询改写：实现与开发集实验

## 在线行为

`rag/query_rewriter.py` 使用当前问题和当前会话最近历史，生成独立检索问题。
无可用历史时直接保留原问题，不额外调用云端。
有历史时使用现有云端模型，temperature=0，JSON 输出，30秒超时，不自动重试。
历史最多12条，每条最多1200字符，总计最多8000字符；这不是Token预算。
输出异常、空文本或过长时回退原问题，并记录状态；不伪装为成功改写。

`rag/pipeline.py` 用改写结果查询菜谱和结构化数据，回答生成仍使用原始问题及历史。
开关为 `RAG_REWRITE_ENABLED`，默认true。关闭可设置false并重启后端。
默认历史和检索命中均可能含个人信息；仅使用用户配置的云端接口，不新增第三方服务。

## 评测方法

与 `dense_dev_raw_v2` 比较，同一v2题库、同一140块语料、同一索引，K=1/3/5，不设阈值。
评测适配器 `evals.adapters:create_rewrite_dense` 与客户端调用同一个改写函数；未使用oracle_question（人工完整问题）或证据标签生成查询。
46道开发题中41道有答案，5道无答案；8道有历史的题执行云端改写，其余直接检索。
未运行44道保留测试题。

## 本次有效结果

| 指标 | 未改写 | 改写后 |
|---|---|---|
| Top-1 证据命中 | 32/41，78.0% | 35/41，85.4% |
| Top-3 证据命中 | 40/41，97.6% | 41/41，100% |
| 多轮追问Top-3证据命中 | 4/5 | 5/5 |
| 话题切换Top-3证据命中 | 3/3 | 3/3 |
| 改写回退 | 不适用 | 0/8 |

多轮题改写增加约0.6至1.1秒调用时间；普通无历史题不增加这次云端调用。
q062“那要蒸几分钟？”补成“蒜蓉虾要蒸几分钟？”，正确操作块由前五未命中变为第一。
q067“醒面要多长时间？”补上“手工水饺皮”，正确块由第三变为第一。
话题切换时保留当前菜名；模型也去除了部分口语前缀，不能宣称每次都严格逐字保持明确问题。

最终有效报告：`outputs/rewrite_dense_dev_v2_fixed/report.json`。
`outputs/rewrite_dense_dev_v2/report.json` 是最初8次改写均因响应压缩解码错误而回退的失败报告，不用于证明效果。
修复方法是云端客户端显式请求 `Accept-Encoding: identity`，避开环境中可选压缩解码库的兼容问题；回答生成客户端也使用该设置。

## 改写后距离阈值回放

| 最大余弦距离 | Top-3证据命中 | 无答案过滤 | 有答案空结果 |
|---|---|---|---|
| 不限制 | 41/41 | 0/5 | 0/41 |
| 0.35 | 39/41 | 5/5 | 2/41 |
| 0.375 | 40/41 | 4/5 | 1/41 |
| 0.40 | 41/41 | 4/5 | 0/41 |
| 0.45 | 41/41 | 3/5 | 0/41 |
| 0.50 | 41/41 | 1/5 | 0/41 |

0.40可作为下一轮验证的候选，不是生产最优阈值。仅5道开发集无答案题，且语义相关但证据不足的问题仍可能通过阈值。
本次没有自动改变客户端阈值，也没有实现检索前意图路由。

## 命令

以下评测会加载本地BGE-M3，并为带历史题调用已配置云端模型：

```powershell
python backend/evals/evaluate_retrieval.py --split dev --adapter evals.adapters:create_rewrite_dense --output backend/evals/outputs/新的目录名
python backend/evals/compare_runs.py backend/evals/outputs/dense_dev_raw_v2/report.json backend/evals/outputs/rewrite_dense_dev_v2_fixed/report.json
```

后续先人工检查更多多轮场景，尤其话题切换、多个菜名和历史冲突，再固定参数运行保留测试集。
不应把当前100%的开发集Top-3证据命中写成实际对话回答准确率。
