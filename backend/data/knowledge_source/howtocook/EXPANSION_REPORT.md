## 3. 筛选、清理与去重规则

### 筛选

- 只收 `dishes/` 下的独立菜谱：一篇文档围绕一道菜，具备原料、用量与可执行步骤，可脱离图片独立理解。
- 排除模板、调味料、半成品、菜单合集、采购/厨具/纯技巧文章、目录页、只有图片或正文过短无法操作的文档。
- 覆盖不同主要食材与烹饪方式（炒、蒸、煮、炖、焖、煎、烤、凉拌、炸），并保留真实存在的相近菜（如红烧肉三个流派、水煮牛肉与水煮肉片、蒜蓉虾与蒜香黄油虾），使语料具备正常检索干扰。
- 未依据现有测评题、题库或标准答案选择菜谱。

### 清理

- 统一 UTF-8（无 BOM）编码，保留原文标题与章节结构，一级、二级、三级标题均为规范 Markdown。
- 仅删除 Markdown 图片、HTML `img` 标签，以及删图后只剩编号或列表符号的残行；未发现徽章、广告或纯展示块。
- 删除 `breakfast/燕麦鸡蛋饼.md` 原文中的 `### 营养成分` 小节（含"预估营养价值（三大营养素）"与热量数据），因其属于无依据支持的热量/营养估算；该文件其余原料、用量与步骤保持原样。
- **按本轮要求，介绍段、预估难度、预估卡路里等原文内容保留在原文件中**，由 `document_loader.py` 在加载时统一清洗；本次未新增这类内容。经加载验证，清洗后的文档中已无"预估卡路里""营养成分""kcal"等内容。
- 未总结、未压缩、未扩写；用量（含"适量""少许"）、单位、时间、温度、可选项与条件限制均按原文保留。
- 新增文档未添加热量估算、营养评价、难度星级等原文之外的信息。
- 文件名沿用原菜名，检查并确认无 `< > : " / \ | ? *` 等 Windows 非法字符。

### 去重

- 三重校验：原始来源路径唯一、菜名（`title`）唯一、正文（去空白后 SHA-256）唯一；300 篇全部通过。
- 与原有 30 篇重复的候选一律跳过，旧文件保留不动。
- 同一主配方及其蘸料、酱汁、可选步骤留在同一篇，未拆篇。
- 简繁体、标点或文件名后缀差异不作为独立菜谱。

## 6. 加载与分块验证

在项目既有 `rag` conda 环境（Python 3.12.8，langchain-core 1.7.6）中直接调用现有函数，未修改任何程序：

- `backend/rag/document_loader.py::load_recipe_documents` → **加载 300 篇文档**，无异常。
- `backend/rag/chunker.py::split_recipe_documents`（默认 `chunk_size=500`、`chunk_overlap=80`）→ **生成 1342 个分块**。
- 分块长度：最短 23 字符、最长 499 字符；**空分块 0 个**。
- 文档清洗后长度：最短 157 字符、最长 4324 字符；**无"只剩标题"的空菜谱**。
- 清洗后文档中不再包含"预估卡路里""营养成分""kcal"等估算内容（0 篇）。
- 分类分布与目录一致：aquatic 28、breakfast 15、dessert 20、meat 98、soup 25、staple 50、vegetable 64。
- 菜名重复：0。
- 章节分布：必备原料和工具 317、计算 306、操作 457、附加内容 262。

### 发现的问题

1. 有 16 篇清洗后正文不足 320 字符（最短为 `话梅煮毛豆` 157 字符）。逐篇检查确认仍含原料、用量与完整步骤，可独立操作，故保留；后续如需提高检索质量，可单独评估。
2. 部分文档的"附加内容"仅含原文贡献邀请句，加载器清洗后该章节为空，分块器自动跳过，不产生空分块。
3. 加载器会删除一级标题与首个二级标题之间的全部内容，因此源文件中的介绍段与预估行不会进入索引；新增文件按本轮要求保留这些原文内容，未额外补充。
4. 本地源数据无 `.git`，版本只能记录到 `package.json` 的 `1.6.0`。
